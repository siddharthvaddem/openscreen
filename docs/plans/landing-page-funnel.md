# Auto Screen Landing Page + App Conversion Funnel Plan

> **For Hermes:** 이 문서는 랜딩페이지, 다운로드, 앱 첫 실행, 로그인, 결제, 사용 시작까지의 전체 전환 퍼널 기준안이다.

**Goal:** 사용자가 웹 랜딩페이지에서 제품을 이해하고, OS별 앱을 다운로드하고, 로그인/회원가입 후 Free 또는 Pro로 자연스럽게 진입하도록 한다.

**Architecture:** 퍼널의 중심은 웹 랜딩페이지다. 랜딩페이지는 제품 설명, 기능, 가격, 사용 방법, 다운로드를 담당하고, 데스크톱 앱은 설치 후 로그인/회원가입과 실제 사용을 담당한다.

## 앱 첫 실행 기준

### 확정
앱을 처음 열었을 때는 editor가 아니라 **로그인/회원가입 화면**이 먼저 보여야 한다.

이유:
- 계정 기반 entitlement 구조와 맞음
- 결제/복구/기기제한/구독 판정이 쉬움
- 향후 클라우드 기능 확장에 유리
- 랜딩페이지와 앱 퍼널이 일관됨

### 예외
- `나중에 둘러보기` guest 모드 허용 가능
- 하지만 핵심 유료 기능은 잠금 유지

## Copy Principle
- 랜딩페이지는 판매/이해 중심
- 앱 첫 화면은 진입/전환 중심
- 기능 설명은 과장 없이 현재 기능 위주
- 아직 미구현 기능은 `곧 제공` 또는 `예정`으로 표시

---

## Download Delivery Model
- 웹에서 OS 감지 후 해당 다운로드 버튼 강조 가능
- 하지만 항상 3개 버튼 모두 노출
- 파일명 예시:
  - `Auto-Screen-mac.dmg`
  - `Auto-Screen-win.exe`
  - `Auto-Screen-linux.AppImage`

---

## Acceptance Criteria
- 랜딩페이지에 OS별 다운로드 버튼 3개가 있다
- 가격 섹션에 월 15,900원 Pro 플랜이 명확히 보인다
- 사용 방법 섹션이 하단에 있다
- 앱 첫 화면은 로그인/회원가입 화면이다
- 랜딩페이지와 앱의 가격/기능 문구가 일치한다
